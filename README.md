# Технадзор автодорог РК — панель контроля КАЖ

Веб-приложение для цифрового технического надзора на автодорогах Казахстана —
не только платных, но и республиканских / местных, по всем 16 областям.
Инженеры технадзора вносят данные прямо на объекте (приёмка этапов, акты скрытых
работ, дефекты, объёмы работ к оплате), а КАЖ видит все решения технадзора на
единой панели, может их подтверждать или оспаривать, следить за статистикой по
дорогам и подрядчикам — то есть осуществляет **надзор над технадзором**.

## Выбор дороги

Форма технадзора использует каскадный выбор:

1. **Область** — все регионы РК.
2. **Тип ремонта** (необязательно) — строительство и реконструкция /
   реконструкция / капитальный ремонт / средний ремонт — сужает список дорог.
3. **Дорога / участок** — реестр из 230+ реальных участков, взятый из отчёта
   по дефектам и гарантийным периодам.

Километраж указывается вручную (участки внутри одной дороги часто отличаются).
Если нужной области, типа ремонта, дороги или вида работ нет в списке — в любом
из этих полей можно выбрать **«+ Добавить свой вариант»** и вписать значение
вручную (реестр не покрывает 100% случаев, особенно локальные дороги).

## Модель данных

Четыре типа записей, единый журнал:

- **Приёмка этапа** — подтверждение, что выполненный этап работ соответствует
  проекту (заключение «соответствует» / «не соответствует», объём план/факт).
- **Акт скрытых работ** — фиксация состояния работ, которые нельзя будет
  проверить визуально после того, как их закроет следующий слой (например,
  основание дороги перед укладкой асфальта).
- **Дефект** — выявленное нарушение с требованием устранения в срок,
  фотофиксацией "было/стало" и уведомлением подрядчика по email.
- **Объём работ** — объём, предъявляемый подрядчиком к оплате (кол-во × цена).

Каждая запись содержит: дорогу, километраж/участок, подрядчика, инженера
технадзора, геолокацию, фото с камеры и **статус надзора КАЖ**
(не проверено / подтверждено / оспорено).

## Роли

- **Технадзор** (инженер на объекте) — вносит записи через форму «Форма
  технадзора». Замена бумажных актов и журналов работ.
- **КАЖ** — просматривает панель, подтверждает или оспаривает решения
  технадзора, видит сводку по дорогам и подрядчикам (открытые дефекты,
  несоответствия, оспоренные решения, суммы к оплате).

## Технологии

- React + Vite, без бэкенда — все данные хранятся в `localStorage` браузера
  (для реального пилота на несколько устройств нужен бэкенд, см. ниже).
- Реальная геолокация через `navigator.geolocation` (нужен HTTPS или
  localhost — иначе браузер не даст доступ).
- Реальная камера через `getUserMedia`, с возможностью сделать несколько
  кадров и удалить неудачные перед сохранением.
- Интерактивная карта Казахстана (Leaflet + OpenStreetMap).
- Email-уведомления подрядчику через EmailJS (бесплатный тариф) — работает
  без сервера; если не сконфигурировано, приложение работает в демо-режиме
  (уведомление показывается в интерфейсе, реальное письмо не уходит).

## Локальный запуск

```bash
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173`. Камера и геолокация в браузере
на телефоне потребуют HTTPS — либо тестируйте на `localhost` с компьютера,
либо используйте задеплоенную версию (см. ниже).

## Настройка email-уведомлений (EmailJS)

1. Зарегистрируйтесь на [emailjs.com](https://www.emailjs.com) (бесплатно:
   200 писем/мес).
2. Создайте Email Service и Email Template с полями `to_email`, `subject`,
   `message`, `photo_attachment`.
3. Скопируйте `.env.example` в `.env` и заполните:
   ```
   VITE_EMAILJS_SERVICE_ID=...
   VITE_EMAILJS_TEMPLATE_ID=...
   VITE_EMAILJS_PUBLIC_KEY=...
   ```
4. Пересоберите проект (`npm run build`) или перезапустите `npm run dev`.

Без этих переменных приложение работает и без ошибок — просто в демо-режиме.

## Деплой на GitHub Pages

```bash
npm run deploy
```

Это соберёт проект и опубликует папку `dist` в ветку `gh-pages`. В настройках
репозитория (Settings → Pages) укажите источник **gh-pages branch**. Сайт
будет доступен по адресу вида `https://<username>.github.io/<repo>/`.

Обратите внимание: GitHub Pages бесплатного тарифа работает только с
**публичными** репозиториями.

## Ограничения текущей версии (MVP) и дальнейшее развитие

- Данные хранятся в `localStorage` — только на одном устройстве/браузере,
  не синхронизируются между технадзором и КАЖ автоматически. Для реального
  пилота на несколько объектов и пользователей нужен общий бэкенд (например,
  Firebase, Supabase или собственный API) — тогда записи технадзора будут
  сразу видны в панели КАЖ на другом устройстве.
- Лабораторные испытания (плотность, прочность бетона и т.д.) в MVP не
  реализованы — следующий шаг развития.
- Нет ролевой аутентификации (логина) — в реальном проекте нужно разделить
  доступ технадзора, подрядчика и КАЖ по учётным записям.
- Исполнительная документация (акты, схемы, журналы) пока хранится как
  отдельные записи, а не как формируемый по шаблону итоговый документ —
  можно добавить экспорт в PDF/Excel.
